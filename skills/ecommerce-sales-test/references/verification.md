# 测试与技能副本范围

## 单元测试

在仓库根目录运行：

```powershell
backend/.venv/Scripts/python.exe -m pytest skills/ecommerce-sales-test/tests -q
```

覆盖：错误查询、截断、空结果、缺失总计、非法金额、负净销、达人归并、日期/任务/口径不一致的基准、未来基准、HTML转义、工作区路径约束。

## 创建副本与验证

```powershell
backend/.venv/Scripts/python.exe skills/ecommerce-sales-test/management.py install
backend/.venv/Scripts/python.exe skills/ecommerce-sales-test/management.py exercise
backend/.venv/Scripts/python.exe skills/ecommerce-sales-test/management.py verify
```

management.py 是本地配置和验收工具，不会被导入为员工技能。它复用既有应用接口函数和工具执行能力，不修改系统源码、不启动常驻服务、不向技能注入密钥。新增资源记录在 state/registration.json，重跑复用副本。

当前使用独立stdio MCP适配器 adapters/mcp_server.py，通过已有MCP配置接入，仅向测试副本绑定私有 ecommerce_sales_preview 工具。模型只传date；适配器检查员工、技能和数据源授权，调用现有查询工具，在本地将原始数据交给固化脚本。查询和计算不依赖模型搬运明细，完整HTML通过平台既有交付和分享接口发布，返回publication入口，不再让模型重建报告。适配器会读取平台的正常宿主配置，但不会把密钥传给技能脚本或模型。

适配器自带 185 秒截止时间与发布宽限；所有业务失败（含超时）都以结构化 `status/stage/retryable/message` 作为正常工具结果返回，不再让平台 MCP 客户端先超时。该工具在平台侧关闭 POST 幂等键（`idempotency.enabled=false`），重复保护由技能自己的输入指纹与成功预览记录负责；否则一次 240 秒超时会被记为 `outcome_unknown` 并锁死同帧重试。

验收必须同时满足：真实预览工具完成、脚本退出0、报告与快照存在、没有Shell调用；runtime_error_code非空或缺少执行回执均以失败退出。原始测试数据和验收记录保存在已忽略的state/目录。

## 2026-10-28 第三版失败与修复

- 11:05 的真实验收失败：调用 11:05:36→11:09:36 恰好 240 秒，工作区已创建但没有 `summary.json`，确认卡在“实时销售汇总”查询。
- 根因：该查询 10:59 耗时约 75 秒、11:05 上游瞬时变慢超过 232 秒；连接器 `read_timeout=模板超时120×2=240s` 与外层 MCP 240 秒几乎同刻到期，外层先超时后调用被记为 `outcome_unknown`，平台按 POST 幂等语义拒绝同帧重试。
- 复核同一查询在 11:18 用 66 秒正常返回 60 行，属于上游瞬时慢查询，不是长期故障。
- 修复（仅技能包）：适配器增加 185 秒截止与发布宽限、阶段化结构化失败、超时前主动取消发布；工具配置关闭平台 POST 幂等键；技能规定 `timeout` 可重试一次，其余失败直接报告阶段。

第一版沿用当前查询模板，因此原模板的业务口径与TOP18限制依然存在。这里没有旧系统专用ClickHouse矩阵和4K看板的全部补充数据，不保证与旧生产大屏完全等价。

独立技能只输出预览，不维护成功发送基准。第二版在state/preview-history.sqlite维护成功预览基准，按租户/员工/任务/业务日期/技能与查询契约隔离；只有完整报告成功发布才提交。失败回滚、旧数据拒绝覆盖、并发串行、相同输入复用有效链接。原任务与分享链接不改动；测试任务为暂停状态，没有接收人。复制过程只保留查询、数据权限、知识资源，关闭复制过来的通知技能。
